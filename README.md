# CareDose 安心盒

面向异地家庭的用药记录、异常协作与医疗信息交接 Web MVP。全部默认数据为虚构示例，摘要为确定性演示摘要；无 API Key 即可运行。

## 运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
npm run test
npm run build
```

打开终端显示的本地地址。使用浏览器原生打印，在目标打印机中选择“另存为 PDF”。生产部署需要将未知路径回退至 index.html，以支持 React Router。

## 目录

- `src/domain/model.ts`：类型、每日任务生成、规则引擎、不可覆盖的事件日志。
- `src/domain/model.test.ts`：状态、来源校验、授权与序列化测试。
- `src/store.ts`：Zustand 单一状态与 LocalStorage 持久化。
- `src/services/summary.ts`：结构化摘要契约、确定性摘要、严格事实校验、文本导出。
- `src/main.tsx`：八个页面、共享组件与路由。
- `src/style.css`：响应式界面、父母大字号、焦点反馈、打印布局。
- 原有 Markdown PRD 与 HTML 原型保留作为产品依据。

## 演示路径

每条独立演示前，可在“设置与授权”重置数据。演示时钟从 2026-10-09 07:55 开始，不跟随真实墙钟。

A 正常用药：药箱模拟器 → 推进 5 分钟至 08:00 → 选择药物 A 并开盖 → 父母端点击“我已服用” → 家庭协作查看同步结果 → 时间线检查独立的开盖与确认事件。

B 异常协作：模拟器推进 5 分钟 → 开盖但不确认 → 推进 15 分钟，父母收到核实提醒 → 再推进 5 分钟，子女收到应用内通知 → 家庭协作选择联系结果并保存 → 任务仍待核实 → 父母端可事后确认。

C 医疗交接：家庭协作 → 生成医疗交接卡 → 检查药物、最近确认、七天未确认项和来源 → 复制或打印 → 设置撤销查看/导出授权 → 再访问交接卡、家庭协作或时间线，验证门禁。

## 已实现

八个路由页面；既定每日计划录入；按有效日期生成任务；主动确认与跳过；设备开盖、关盖、离线、恢复；跨日演示时钟；可配置分级通知；联系结果记录；事件元数据与 ID 追溯；查看/导出/联系人授权；授权审计；七天动态摘要；复制与手动复制降级；浏览器打印；刷新持久化；重置演示数据；移动端布局与父母端大字号。

## 技术决定及原型差异

按照本次需求使用 React、TypeScript、Vite、Tailwind CSS、Lucide、Zustand、React Router，替代 PRD 第 8 节单文件 HTML 交付。以 Markdown 为业务依据，补齐 HTML 缺少的关盖、多任务、分级通知和审计。设备状态独立于任务状态，任何设备事件或子女联系均不代替父母主动确认。

模拟数据存放在一个 Zustand store，通过 LocalStorage 保存。跨页面即时同步；并非跨设备实时同步。刷新恢复本地状态；多标签页并发写入不属于当前保证范围。授权是演示级页面与服务门禁，不能替代正式服务端身份认证，拥有浏览器开发工具的人可以读取本地数据。

摘要由结构化 JSON 确定性生成，所有事实由规则计算。运行时校验器严格匹配事实字段与文字，拒绝新增药名、剂量、时间、来源或医疗结论。默认使用 Mock Mode。可选 Node 服务端代理已实现：将 `.env.example` 复制为 `.env`，配置 `MODEL_API_URL`、`MODEL_API_KEY`、`MODEL_NAME`，运行 `npm run server`，在交接页面勾选尝试服务端 AI。上游需接受 chat-shaped JSON（model/messages/response_format），并返回 choices[0].message.content 中的 JSON。密钥只在 Node 进程读取。Vite 将 /api 代理到本机 8787。未配置、服务未启动、超时或校验失败均回退确定性摘要。当前严格校验要求保持全部字段及值；为事实安全，暂不允许自由改写摘要。生产需配置同源反向代理与服务端认证。真实模型联网调用未验收，当前没有提供模型密钥。

## 验证

运行 `npm test` 验证开盒不确认、确认幂等、事后确认、分级提醒、离线独立、联系不代确认、跨日去重、跳过、摘要来源与篡改拒绝、撤销授权、序列化保留。

构建及实际测试结果见 `VALIDATION.md`。浏览器原生 PDF 输出需在支持打印的浏览器中完成。

本产品仅用于用药记录与信息交接，不提供疾病诊断、药物推荐或紧急救援服务。紧急情况下应立即联系当地急救服务。
